# 个人知识库、官方资料库与阅读器

核验日期：2026-11-17。本文记录当前实现，不代表完整文献管理或块知识库已经完成。

## 领域和权限

沿用 `materials`，增加 `library_scope`、`folder_name`：

| scope | 生命周期 | 可见与维护规则 |
| --- | --- | --- |
| personal | private → archived | 用户上传即私有保存，无需审核；只有本人可读和维护；不进入公开审核队列 |
| official | approved → archived | 管理员发布、编辑和下架；已发布内容公开可读；管理员入口位于用户端官方资料库 |
| community | pending → approved/rejected/hidden | 保留历史社区资料及审核流程；审核通过不意味着官方原创 |

`/library` 包含本人私有资料和收藏的已发布官方资料；`/official-materials` 是公开官方入口；`/materials` 保留社区兼容入口。官方收藏复用 `material_favorites`，幂等加入/移除，不复制原件。官方下架后不能继续访问原件，收藏不绕过状态校验，既有学习记录保留。

个人资料禁止通过现有分享 API 公开，旧分享 token 也不能解析。公开查询、附件、搜索、审核显式排除 personal。登录搜索额外包含本人 private 资料，并检查当前账号状态。

## 官方资料目录与管理

官方资料新增来源与出版元数据：`materialType`（book/paper/lecture/exercises/course/other）、`author`、`sourceUrl`、`publicationYear`、`edition`、`licenseStatus`（unknown/self_owned/authorized/open_license/public_domain）。旧数据类型默认 other、授权默认 unknown，作者等可空；旧调用不传元数据时仍兼容，不把历史记录自动认定为已获授权。来源只接受无凭据的 HTTP/HTTPS 链接，年份为0（未设）或1000至当前年+1，类型与授权使用精确枚举校验。个人／社区请求不能通过这些字段获得官方身份。

公开官方目录使用服务端关键词（标题、作者、简介、标签、文件名）、分类、资料类型筛选，以及更新时间／标题排序；分页默认20条、最多50条，稳定次序中包含ID。分类选项来自对应公开／管理状态范围，汇总收藏数与评分批量读取；分页结果不返回个人进度。跨分页的 `?selected=id` 深链会补读指定公开详情，无法访问时显示错误而非误选其它资料。

管理员在用户端官方资料库点击“管理官方资料”，可查询全部、已发布、已下架和历史隐藏资料。下架必须填写最多500字原因，状态变更与审计在同一事务；重新上架会验证原 PDF 可读，保留资料ID、原附件、收藏、阅读进度和批注。元数据更新不写生命周期状态，旧编辑不能复活已下架资料。已下架条目不提供公开阅读和下载入口。

官方资料不再进入社区投稿审核队列，管理端通用资料列表标记 `libraryScope`，引导到官方专用管理入口；旧通用审核修改官方状态返回409，避免绕过专用校验。管理员官方维护入口仍在用户端，管理端没有重复实现一套编辑器。

当前版本字段只是版本说明，不包含新旧文件版本关联或批注迁移；原附件仍不可直接替换。授权状态由维护者记录，未实现自动授权核验；官方文件仍归上传管理员计费，平台资产归属、独立配额、评分前端、内容反馈与全文索引仍是后续工作。

## 原文件保存

1. `POST /api/v1/files` 使用带认证的 multipart 上传。
2. 原文件保存到 `UPLOAD_DIR/YYYYMMDD/UUID.ext`。默认 `UPLOAD_DIR=../storage/uploads`，相对于后端工作目录；生产应使用绝对持久化路径。
3. MySQL `file_records` 保存 owner、原始名称、服务端识别 MIME、大小和内部路径；API 的兼容 `path` 字段为空，不暴露服务器路径。
4. 创建资料通过 `attachmentFileId` 关联，并检查文件归属，不能把他人私有文件挂入公开资料。
5. 原件经 API 权限校验后交付，不通过静态上传目录公开。私有 PDF 使用 Authorization header，不在 URL 放令牌。

单文件上限 50 MiB。2026-11-17 起新上传仅接受 PDF，前后端分别检查扩展名与 `%PDF-` 文件签名。新建资料关联附件时检查归属、扩展名、MIME 与实际磁盘内容，不能复用历史非 PDF 的 fileId 绕过。Word、文本和图片不再允许新上传；历史原件保留下载，未换附件时仍可编辑元数据，旧封面关联保持兼容。文件写入或数据库记录失败会清理本次原件。

上传与资料创建是两次请求：取消或创建失败可能留下未关联文件，页面重试复用上传 ID。自动孤立文件回收、分片上传、对象存储尚未实现。

### 容量配额与待核查文件

`UPLOAD_USER_QUOTA_BYTES` 为每个上传账号统一设置容量，默认 `1073741824`（1 GiB），只接受正整数，非法值拒绝启动；单文件仍不超过 50 MiB。管理员上传也计入本人配额，不设隐式豁免。按本人所有 `file_records.size` 计量，历史非 PDF、未关联上传、已归档原件均计入；收藏仅引用官方原件，不占收藏者额外容量。已有超额文件保留，新增上传被拒绝。

上传先预检查，再以真实磁盘写入字节进行最终校验。MySQL 事务首先锁定当前用户行，再汇总文件占用并创建记录，同账号跨实例上传不能同时越过剩余容量；失败清理本次原件，不删除历史文件。HTTP `409/storage_quota_exceeded` 表示容量不足。上传占用与绑定资料分两次写入，资料保存失败时已上传文件仍计费；页面重试复用文件 ID。

认证 `GET /files/storage` 返回当前账号的 `usedBytes/quotaBytes/remainingBytes/fileCount/unlinkedFileCount/unlinkedBytes` 和最多20条 `unlinkedFiles`（`id/originalName/size/createdAt`），按上传时间倒序、ID稳定排序，不返回磁盘路径。容量页支持刷新／失败重试，上传成功或失败后刷新统计；个人库与管理员发布官方资料时均可查看。

待核查文件仅指未被资料附件／封面、图谱缩略图或模板预览显式引用的上传，归档资料仍是引用；它们可能被笔记或图谱的历史非结构化链接使用，**不等于可以安全删除的孤立文件**。当前仅展示，不自动或物理清理。删除资料仍只是归档，不释放磁盘容量。完整引用核验、可恢复回收、永久删除与容量释放另列工作包。

## API

以下路径均带 `/api/v1` 前缀。

| 方法和路径 | 用途 |
| --- | --- |
| GET `/files/storage` | 当前账号容量占用、配额及最近20条无显式关联文件，仅本人可读 |
| GET/POST `/library/materials` | 本人私有及官方收藏列表／创建私有资料 |
| GET/PUT/DELETE `/library/materials/:id` | 可读详情／本人元数据编辑／本人归档 |
| GET `/library/materials/:id/attachment` | 登录后按权限预览原件，`download=1` 下载 |
| GET `/official-materials` | 公开查询已发布官方资料 |
| GET `/official-materials?page=1&pageSize=20` | 官方服务端分页目录，支持q/category/materialType/sort；无查询参数时保留旧数组响应，有查询参数时返回items/total/page/pageSize/categories |
| GET `/official-materials/manage` | 管理员专用分页目录，可按status=all/approved/archived/hidden过滤；普通用户禁止访问 |
| POST `/official-materials` | 管理员发布 |
| PUT/DELETE `/official-materials/:id` | 管理员编辑／归档下架 |
| PUT `/official-materials/:id/status` | 管理员发布／下架，body为status:approved或archived及reason；下架原因必填；旧DELETE以默认原因兼容 |
| PUT/DELETE `/library/collections/:id` | 登录用户幂等收藏／移除官方资料 |
| GET `/materials/:id/attachment` | 保留公开资料原件访问，`download=1` 下载 |

新域的创建、编辑、归档与审计使用同一 SQL 事务。编辑仅更新元数据，归档仅更新状态，避免旧编辑覆盖下架状态。原文件不允许直接替换，上传新版本需创建新资料，保护已有页码锚点。

删除为 archived，保留来源身份与原件，并非物理清除；当前无回收站、恢复按钮和永久删除。

## 个人书架界面

个人库采用小说书架式封面网格。PDF 接近视口时，从受保护附件接口读取文件并在浏览器渲染真实首页封面；最多同时打开两份封面文档，图像尺寸限制为 320×480 内，完成后释放 PDF 实例和 canvas。封面对象 URL 仅存当前组件内存，卸载、换账号或令牌时取消待处理任务并释放，不写入服务器或浏览器持久缓存。401 通过现有会话恢复流程重试一次。尚未加载、失败、历史非 PDF 或不支持 IntersectionObserver 时保留标题排版封面，失败可手动重试。

悬浮或键盘聚焦封面时显示详情小框，包含简介、原文件、分类、文件夹、标签及更新时间；Escape 可关闭。弹层受视口约束，支持内部滚动；点击封面选中下方阅读、下载和管理操作，触屏不依赖悬浮。窄屏两列，搜索、文件夹筛选与官方收藏保留。

## 阅读与批注

书架和详情展示当前用户的真实阅读进度、页码和最近阅读时间，支持阅读状态筛选、最近阅读排序和保存页码续读。受保护的个人库列表和详情返回可选 `readingProgress`（`currentPage/totalPages/progressPercent/lastReadAt`），按当前用户与可读资料 ID 批量查询；公开官方／社区列表不返回个人阅读状态。编辑元数据保留阅读进度，未知总页数不提前判为已读完。

- PDF 由 PDF.js/react-pdf 渲染，Vite 从 react-pdf 的依赖位置统一解析 `pdfjs-dist`，保证 API、文字层样式和 worker 使用兼容版本。
- 捕获真实文字选区多个矩形，以页内归一化坐标保存并覆盖高亮；缩放、重新打开、`page/annotation` 深链均可定位。
- 进度和书签保存到 MySQL `reading_progresses`；批注按 user/material 保存在 MySQL `pdf_annotations`，当前并未迁入 MongoDB。
- 批注与原件分离且用户间隔离；下载不含 StudyMate 批注，尚无带批注 PDF 导出。
- 进度串行合并、防重复写入，失败可重试；同用户刷新令牌不清空未保存批注与待重试进度。PDF 加载失败有重试入口，401 尝试一次共享会话恢复。
- 批注可删除、选色、定位、生成卡片/图谱草稿；摘录到笔记转义文本，保留资料、页码和批注回跳链接。
- 已移除 Word 新上传/保存入口；历史 Word 仅保留原件下载与格式提示，不再规划 Word 在线转换。
- PDF 内嵌目录按需读取，支持层级与文内跳页，不执行外部链接；连续点击以最后选择为准，无目录时显示空态。
- 当前 PDF 正文查找复用已加载实例，逐页提取文字，提供扫描进度、上下文、上一处／下一处及转义后的文字层高亮，支持取消和失败重试；扫描完成保留用户选中的结果。最多显示 500 处匹配并说明已扫描范围，文字缓存最多 32 页；换文档和卸载使旧异步结果失效。
- 页面缩略图复用阅读器现有 Document，不为缩略图重新下载文档；每组最多渲染 8 页，支持上一组／下一组、回到当前页、键盘与点击跳页、当前页标记和失败重试。与目录／搜索互斥，关闭或换文件即卸载，跳页沿用原阅读进度保存链路。
- 查找只覆盖当前 PDF 的文字层，扫描件无文字时提示需要 OCR。OCR、跨资料全文索引、带批注导出、跨资料摘录池、文献元数据和引用格式仍待实现。封面当前为客户端即时生成，服务端缩略图持久化与分页书架另列后续优化，资料较多时仍有重复读取原件的成本。

## 迁移与运维

新增 `010_material_libraries.sql`，后端启动迁移器自动执行幂等上行，历史资料默认 community。回滚先归档 personal/official，再删除新列，避免私有资料落回公开旧路径；回滚会丢失 scope/文件夹元数据，须用数据库备份恢复。

`011_official_material_catalog.sql` 幂等增加7个来源／版本／授权／下架原因字段，后端迁移器执行。011回滚只删除本轮字段，保留scope、状态、资料ID与原件；字段数据不可从重新上行中恢复，需数据库备份。上线时应先执行后端迁移，再使用新版官方目录页面。

备份须同时包含 SQL 与 `UPLOAD_DIR` 原件，笔记内容文档/快照另需 MongoDB 备份。多实例需共用持久存储；本轮未接 MinIO/OSS。

## 验收与验证边界

1. A 私有上传 PDF 后立即阅读、划选、保存、刷新/缩放恢复、下载、摘录创建笔记；B 和匿名不可读 A 的详情和原件。
2. 管理员发布官方资料，用户收藏/移除；取消不删原件，下架阻止继续读取。
3. 新上传拒绝 Word、图片和改名伪 PDF；旧 Word 保留下载，不出现 iframe 或错误 PDF 渲染。
4. 审计失败完整回滚，并发旧编辑不复活下架资料。
5. `e2e/v1-pdf-navigation.spec.ts` 使用真实三页 PDF 验证桌面与 390px 窄屏的书架续读、内嵌目录、正文匹配高亮和返回书架更新进度；API 由测试模拟。

测试入口：`go test ./...`、用户端 Vitest、`e2e/v1-library-reader.spec.ts`、`e2e/v1-study-loop.spec.ts`。浏览器测试模拟 API，但使用真实 PDF、文字层、几何和下载；后端 HTTP/SQLite 测试覆盖实际服务权限。`TestMySQLMaterialLibrariesMigrationAndLifecycle` 使用独立临时 MySQL 数据库验证重复迁移、权限、收藏、回滚，不修改业务库。
